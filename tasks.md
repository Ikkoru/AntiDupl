## P0 — Bugs

- [ ] **T26 A hot key is sometimes ignored** (user's report: delete or mistake, now and then, seemingly at random; not yet proven). Two candidates in the code. (1) Each action runs through `ProgressForm.Execute`, which after 200 ms opens a modal progress window whose `OnKeyDown` marks every key handled, so a key pressed while it is open is lost; it closes on a 100 ms timer, and the list updates only after that. (2) Hot keys act only when the results list has the focus: `MainSplitContainer` passes them on only when it has the focus itself, and a key sent to the tool bar's lists or the preview does nothing. T17's key events (`to`, `window`, `progressWindowOpen`) tell which: after the user reports a miss, find the key event with no action after it.

- [ ] **T19 Crop search in two stages** (design from the study, [07](plan/07-settings-study.md) § Crops; proposal before code). Every metric that compares whole pictures ranks crops among the versions, so crops need: (1) candidates from a crop-tolerant descriptor per image (SSCD-like embedding: no unrelated pair let through in the set; a colour histogram is free but will mistake more pictures in a large collection), (2) ORB keypoints per image (3 ms, about 38 kB) to align each candidate pair (about 1 ms), (3) local colour on the overlap to tell a crop of a copy from a crop of a version. Upstream's deep search (#254, merged; the WPF front end only, `AntiDupl.NET.Deep` and `AntiDupl.NET.Onnx`) has (1) and (2) in another form: DINOv2-base embeddings through ONNX Runtime, clustering, and a SuperPoint + LightGlue check; it reports the embedding similarity, so copies and versions come mixed. Proposal for (3) on top of it: the workspace's `reference\github-drafts\issue-crop-search.md` (after the T10/T11 one). Open: the Windows Forms front end has no deep search.

## Notes for the implementing session

* Code in the plan is a sketch written without a compiler (the C++ core builds only on Windows/MSVC) — verify each change in the app.
* There are no automated tests; each plan document ends with a manual test list.
* Image DB: `<user folder>\images\128x128\` (release: `%LOCALAPPDATA%\AntiDupl.NET\user`; personal build: `user\` next to the program; dev builds: the `-s` folder). Each `FILE_VERSION` bump (`adConfig.h`) costs one full re-scan.
