## P0 — Bugs

- [x] **T0 ⬆ Build fails from folders with spaces/commas** (the user's case). Merged upstream (PR #244).
  * The C# build events (`AntiDupl.NET.WinForms.csproj:43` → `CopyData.cmd`, `AntiDupl.NET.Core.csproj:75` → `External.cmd`) quote their paths; both scripts take `%~1`/`%~2` and quote every expansion.
  * A comma also broke the Release link: `link.exe` cuts the `/LTCGOUT` (.iobj) and incremental-LTCG (.ipdb) paths at a comma (C1083 / LNK1104), and only for plain-ASCII paths. Release|x64 uses plain `/LTCG` without `/LTCGOUT`.
  * Tested: unmodified master fails, the fix builds (x64 Release, DLL loads, all resources copied) under `…\Coding, etc\Claude Code\Anti-Dupl\AntiDupl.NET`, `C:\ad\T0 x, y` and a folder named ``T0 [a] (b) & c, d=e! ^f ~g #h +i @j {k} $l 'm' `n é 日本 😀``. Still unsupported, by MSBuild/vcpkg themselves: `%` (MSBuild's temporary batch files, vcpkg's MSBuild integration) and `;` (MSBuild's list separator). A `$` followed by letters builds, but vcpkg's MSBuild integration writes its compiler-hash cache file to a path with that part dropped. vcpkg can't build its MSBuild-based ports (Simd) under a path with a comma: `vcpkg_install_msbuild` passes `/p:VcpkgInstalledDir=<install folder>` unescaped and MSBuild splits it at the comma. Such a checkout builds only while vcpkg's binary cache already holds those packages.

- [x] **T25 ⬆ A file with a path over 260 characters was deleted for good.** Merged upstream (PR #263). `FileDelete` sent any path of `MAX_PATH` or more to `DeleteFile`.
