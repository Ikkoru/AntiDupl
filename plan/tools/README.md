# Reproduction & experiment tools

Python 3.10+. `pip install -r requirements.txt`. Nothing here is part of the build; it exists so every number quoted in [`../`](../README.md) can be re-checked on your machine (the scripts run on Windows too). "Current" in `adsim.py`, `repro_difference.py` and `float_noise.py` means v2.3.13, before the fixes.

| Script | What it shows | Example |
|---|---|---|
| `adsim.py` | Library: bit-faithful copy of AntiDupl's reduced-image pipeline (gray conversion, Simd bilinear resize, 2×2 reduce) and of the current float32 SSIM arithmetic, plus the proposed fixed versions. | — |
| `repro_difference.py` | For image pairs: which decoder the current build uses per file, the Difference the current build shows, and the value after the fixes. `--size N` = AntiDupl's *Reduced image size* (default 128, the user's setting; AntiDupl's own default is 32). | `python repro_difference.py "Identical but 0.22 (1).jpg" "Identical but 0.22 (2).jpg"` → current `0.217453` (shows **0.22**), after fixes `0`; with `--size 32` current `0.179443` (shows **0.18**) |
| `float_noise.py` | ~30 % of *identical* 128×128 planes get Difference 7.6e-6 / 1.5e-5 with the current arithmetic → shown as 0.00 but not green, and dropped at threshold 0 %. | `python float_noise.py a.jpg b.jpg` |
| `metric_experiment.py` | Synthesises duplicates (re-saves, resizes) and variants (colour/local edits, mosaic, text, crops) from your images and compares candidate metrics. Uses the optional external tools below when they are on `PATH` or in a `--tool-dir` / `ANTIDUPL_TOOL_DIRS` folder. | `python metric_experiment.py img1.jpg img2.png --maxside 1024 --tool-dir <libjxl bin folder>` |
| `butteraugli_harness/` | 50-line C++ harness around the standalone `google/butteraugli` (Apache-2.0) used for the timing row in [02](../02-comparison-modes.md). Build line in the file header. Put the binary on `PATH` or in a `--tool-dir` folder as `bh`. | — |
| `core_search.py` | Drives a build's `AntiDupl.dll` directly (no GUI): fresh or given user folder, one search folder, prints every pair's Difference at full precision. Options for reduced size, threshold, libjpeg-turbo, algorithm, repeated runs, and the image database (`--use-db`, loaded and saved like the GUI does); `--details` adds the search time, defect entries, and each image's type, size and EXIF fields; `--collect-threads` sets the decoding threads (timing); `--transformed` also searches rotated and mirrored copies; `--images FILE` writes every image in a result with the core's type, size, blockiness and blurring. Refuses the real `%LOCALAPPDATA%\AntiDupl.NET` user folder and any settings folder with an AntiDupl program next to it (an installed copy's). | `python core_search.py <bin\Release> <scratch user dir> <folder> --size 128` |
| `make_identity_cases.sh` | Pixel-identity test pairs from one image, one folder each: byte copy, metadata stripped, lossless progressive re-save, JPEG vs a PNG of its decoded pixels, PNG vs lossless JPEG XL, one changed pixel, mirror image. Run `core_search.py` on each folder (`--transformed` for the mirror). Needs magick, exiftool, jpegtran, djpeg, cjxl. | `bash make_identity_cases.sh a.jpg cases` |
| `decisions_check.py` | Reads the personal build's decision log (`decisions.jsonl` in the user folder: every action on result pairs, every pair looked at, undo and redo), gives each pair its last decision (deleted, mistake, moved, left) and lists the deleted pairs with the highest difference and the kept ones with the lowest, the ones to ask about. | `py -3 decisions_check.py <user folder>\decisions.jsonl --tsv pairs.tsv` |
| `study_set.py`, `study_metrics.py`, `settings_study.py` | The study of [07](../07-settings-study.md). `study_set.py` builds or extends the sample set from a config naming archive files (kept outside the repository): per case the artist's original, variants and steps, and about 60 derived copies (also ones converted again after a lossy step), crops, overlays, transforms and edits, with a manifest saying how each was made. `settings_study.py` computes every metric of `study_metrics.py` (AntiDupl's own at every setting, windowed and multi-scale SSIM, GMSD, HaarPSI, VIF, CIEDE2000, PSNR, histograms, perceptual hashes of 64 and 256 bits, SIFT alignment, Butteraugli and SSIMULACRA2 through libjxl; with OpenCV, ORB and AKAZE alignment and OpenCV's hashes) on every pair, and per image the quality indicators, among them `jpeg_history` (the strongest JPEG compression the pixels went through, whatever the format now). It judges them on three tasks: copies vs versions (overall and per kind of difference), which copy is worse, crop detection; `--analysis-only` redoes the tables from the saved values. Needs scikit-image, SciPy, ImageHash; libjxl's tools for the slow metrics; OpenCV optional (`opencv-contrib-python`, from the folders in the environment variable `STUDY_PYLIB`). | `py -3 study_set.py <config> <set>`, `py -3 settings_study.py <set> <cache> <results> --dll <bin\Release>` |
| `embed_metrics.py` | Adds neural metrics to a `settings_study.py` run, from the 512 px working copies: embedding distances (SigLIP, SSCD, DINOv2) and learned full-reference differences (LPIPS, DISTS), written to `pairs-embed.csv` next to `pairs.csv` (the columns of the file it replaces that a run doesn't compute are kept); with `--nr`, no-reference quality per image (TOPIQ-NR, MUSIQ, NIQE, BRISQUE) on a central 1024 px crop at full size, written to `quality-nr.csv`; both joined by `--analysis-only`. Needs a Python with PyTorch, torchvision, timm and transformers, and the model files named in its docstring; it fetches nothing from the network. | `<python> -I -B embed_metrics.py <cache> <results> --siglip <file> --sscd <file> --dinov2 <file> --lpips --dists --torch-home <dir> --pylib <dir>` |
| `qs_check.py` | jpegQS on the study set's JPEG copies, full size and reduced: SSIMULACRA2 and Butteraugli's 3-norm against the picture before JPEG (the original, or the PNG of the same reduction) before and after (`-q 3`, `-q 6`), the re-saved file's (missing) gain, and a JPEG rebuilt from the PNG of a JPEG. Needs jpegQS and libjxl's `ssimulacra2` and `butteraugli_main`. | `py -3 qs_check.py <set> <scratch dir> <jpegqs64.exe> <libjxl bin folder>` |
| `webp_reencode.py` | The WebP trace experiment: per file, the change after re-encoding as WebP at each quality; a past WebP save shows as a flat stretch from its quality up. | `py -3 webp_reencode.py <set>\<case> original.png webp-q50.webp webp-q50-to-png.png` |
| `webp_trace.py` | The WebP trace's calibration ([07](../07-settings-study.md)): from the set's never-WebP pictures, WebP copies at known qualities (three encoder settings), chains and never-WebP copies, each with its re-encoding curve and its 4 px grid profile, in one CSV; `--analyze` validates both as detectors and the curve as a quality estimate, one illustration left out at a time. Needs `LIBJXL` (cjxl, djxl) and ImageMagick's `magick`. | `py -3 webp_trace.py <set> <results>\webp-trace\samples.csv --workers 12`, then `py -3 webp_trace.py --analyze <results>\webp-trace\samples.csv` |
| `webp_lattice.py` | The WebP trace in the transform domain, a first test ([07](../07-settings-study.md)): on `webp_trace.py`'s samples of a few pictures per illustration, whether the 4x4 DCT coefficients of VP8's luma lie on a lattice, its score and step, at the sample's grid and at the best of 16 phases; `--analyze` as in `webp_trace.py`, with the quality read from the step. Slow: about 20 minutes for three pictures per illustration on 12 workers. | `py -3 webp_lattice.py <set> <results>\webp-trace\lattice.csv --per-case 3 --workers 12`, then `py -3 webp_lattice.py --analyze <results>\webp-trace\lattice.csv` |
| `sort_check.py` | Sorts a search's results through `adResultSort` with every sort type and direction and checks the rules in its docstring: which image of a pair is on which side, the full row order including ties, the same rows whatever sort came before, and numbers in names by value (`x_p2` before `x_p10`). | `python sort_check.py <bin\Release> <folder> <scratch user dir>` |
| `flashprobe/` | Catches white flashes of windows opening in dark mode: opens one window of a build over a black backdrop, captures the screen where it opens for 0.7 s, and counts near-white frames per run. Variants for the start window (as built, without parts of it, cloaked, with the title set first), an empty window, and *Select columns*; list in the file header. Refuses the real `%LOCALAPPDATA%\AntiDupl.NET` user folder and any settings folder with an AntiDupl program next to it. Windows open on the screen. | `dotnet build -c Release`, then `flashprobe <bin\Release> <scratch user dir> S1 5` |
| `make_jpeg_cases.sh` | Builds JPEG decoder test cases from one JPEG, one folder per case, each a same-pixel pair: chroma subsamplings, gray, progressive and arithmetic coding, each as JFIF-first vs EXIF-first; all seven EXIF fields; EXIF after JFIF; CMYK; truncated. Run `core_search.py --details` on each folder. Needs djpeg/cjpeg, exiftool, magick (or `TJ_DIR` / `EXIFTOOL` / `MAGICK`). | `bash make_jpeg_cases.sh a.jpg cases` |
| `antidupl.ExifTool_config` | ExifTool config that makes the PNG keywords used by ComfyUI / InvokeAI / Fooocus writable. Destination in the product: `data/` next to the exe (see [05-metadata-merge.md](../05-metadata-merge.md)). | `exiftool -config antidupl.ExifTool_config …` |

Optional external tools for `metric_experiment.py`: the libjxl reference builds `ssimulacra2` and `butteraugli_main` (see [`../README.md`](../README.md#tools)), and these Rust ports, which need the Rust toolchain and add nothing the libjxl tools don't measure except DSSIM:

```
cargo install butteraugli-cli                         # 'butteraugli'  (pure-Rust port of libjxl butteraugli)
cargo install ssimulacra2_rs --no-default-features    # 'ssimulacra2_rs' (default features need VapourSynth)
cargo install dssim                                   # 'dssim'
```

The user's `Examples.zip` images are not committed (size/copyright); pass their paths on the command line.
