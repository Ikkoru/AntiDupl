# AntiDupl (Ikkoru fork) — notes for Claude Code sessions

This file, `tasks.md` and `plan/` exist only on the personal branch `claude/inspiring-wright-e741yy` and never go into upstream PRs. Setup of a particular machine (paths, tools, worktrees) belongs in the `CLAUDE.md` of the folder around the clone.

* Work items: [`tasks.md`](tasks.md). Evidence, root causes and designs: [`plan/README.md`](plan/README.md) — read it before changing the comparison code, the options classes or the sorting.
* Build: MSVC C++ (the projects name toolset v143) with vcpkg in manifest mode (`src/vcpkg.json`; CI checks vcpkg out at the manifest's `builtin-baseline`) and the .NET 10 SDK (Core targets `net10.0-windows`, WinForms and WPF `net10.0-windows7.0`). Visual Studio or just its Build Tools, with the C++ and the .NET desktop workloads — without the latter, MSBuild cannot find a standalone .NET SDK: `MSBuild src\AntiDupl.sln -restore -p:Configuration=Release -p:Platform=x64` → `bin\Release\AntiDupl.NET.WinForms.exe`. The first build compiles all vcpkg dependencies and takes a long time.
* **Build the vcpkg libraries with v143, never v145** (MSVC 14.51, Visual Studio 2026's default, which vcpkg picks when installed): it miscompiles libde265 1.0.16, `de265_init()` crashes while `AntiDupl.dll` loads, and the program closes without a message. Pin it with `VCPKG_PLATFORM_TOOLSET v143` in an overlay triplet.
* **Paths with spaces or commas break the build**: the C# build events call `cmd\CopyData.cmd` and `src\AntiDupl.NET.Core\External.cmd` with unquoted paths (task T0).
* **Never run a dev build against the user's real data** (settings, image DB, mistakes list, results). Without `-s`, a normal build uses `%LOCALAPPDATA%\AntiDupl.NET\user` and a `Publish` build uses `user\` next to the exe. Start it with `-s <folder>`; the folder must exist. Do not copy `options.xml` there — it stores an absolute path to the real profile. Test on copies of images: deletions are real.
* Upstream is `ermig1979/AntiDupl` (branch `master`; CI = GitHub Actions on `windows-latest`). Each upstreamable fix (⬆ in `tasks.md`) gets its own branch from `upstream/master`, one fix per branch; the personal branch merges them all.
